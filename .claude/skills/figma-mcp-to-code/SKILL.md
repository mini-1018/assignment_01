# Figma MCP 추출 절차

## 왜 순서가 중요한가

Figma MCP 응답은 노드 크기에 비례해 커진다. 파일 루트에 `get_design_context`부터 부르면 응답이 잘려 일부 화면이 통째로 빠지는데, 이 누락은 조용히 일어난다. 화면 목록을 먼저 확보하고 **노드 단위로** 내려가면 누락을 즉시 알 수 있다.

## 0단계: 링크 해석

Figma URL에서 파일 키와 노드 ID를 읽는다.

```
https://www.figma.com/design/{fileKey}/{name}?node-id={nodeId}
```

`node-id`가 없으면 파일 전체를 가리킨다. 이때는 1단계에서 화면 목록부터 뽑는다.

## 1단계: 구조 파악 — `get_metadata`

파일 또는 페이지 노드로 `get_metadata`를 호출해 프레임(화면) 목록과 노드 ID를 얻는다. 결과를 표로 정리한다.

| 화면명 | 노드 ID | 종류 | 처리 여부 |
| --- | --- | --- | --- |

이 표가 작업 목록이자 누락 검증 기준이다. 표에 있는 모든 화면을 처리하거나, 처리하지 못한 화면을 명시적으로 남긴다.

`_workspace/00_request.md`에 「화면 범위」 표가 있으면 시안 기반 화면만 3~5단계로 추출하고, 시안 외 화면은 처리 여부에 `보류`로 적는다. 시안 외 프레임에는 디자이너 주석이 없으므로 주석을 찾지 않는다.

## 2단계: 토큰 확보 — `get_variable_defs`

변수 정의를 받아 토큰 표로 정리한다. 구현 전에 토큰을 먼저 확정해야 각 화면 구현에서 같은 색을 다른 방식으로 적는 일이 없다.

| 토큰명 | 값 | 용도 | CSS 변수 |
| --- | --- | --- | --- |
| color/bg/default | #FFFFFF | 페이지 배경 | --color-bg-default |

- 변수가 정의돼 있지 않으면 화면에서 반복되는 값을 모아 토큰을 **제안**하고, 제안임을 표시한다.
- 일회성 값은 토큰으로 만들지 않는다. 두 곳 이상에서 쓰이는 값만 토큰이다.

## 3단계: 화면별 컨텍스트 — `get_design_context`

화면 노드마다 따로 호출한다. 한 번에 여러 화면을 요청하지 않는다.

같이 호출하면 좋은 것:
- `get_screenshot` — 레이아웃을 눈으로 확인한다. 텍스트 명세만으로는 간격과 정렬을 놓친다.
- `get_code_connect_map` — 이미 코드와 연결된 컴포넌트가 있으면 새로 만들지 않고 그 컴포넌트를 쓴다.

## 4단계: 에셋 — `download_assets`

아이콘과 이미지를 `public/assets/{화면 또는 도메인}/`에 내려받는다.

- 단색 아이콘은 SVG로 받는다. 색상을 토큰으로 바꿔 쓸 수 있다.
- 사진은 래스터로 받되, 실제 표시 크기의 2배를 넘는 원본은 줄여서 저장한다.
- 파일명은 케밥 케이스로 통일한다.

## 5단계: 명세 작성

화면마다 다음 형식으로 `_workspace/02_figma_design-spec.md`에 기록한다.

```markdown
## {화면명} (node {nodeId})

- 라우트: /{경로 제안}
- 레이아웃: {세로 스택 / 12열 그리드 등}, 최대 너비 {값}
- 반응형: {분기 기준과 각 분기의 변화}

### 컴포넌트 분해
| 컴포넌트 | FSD 위치 | 재사용 | 비고 |
| --- | --- | --- | --- |
| ProductCard | entities/product/ui | 3개 화면 | 이미지, 제목, 가격 |

### 데이터 필드 후보
| 표시 항목 | 예상 타입 | 출처 | 비고 |
| --- | --- | --- | --- |
| 제목 | text | product.title | 2줄 말줄임 |

### 상태
- 로딩 / 빈 목록 / 오류 각각의 디자인 유무. 디자인이 없으면 "미정의"로 적는다.
```

`데이터 필드 후보` 표는 그대로 Supabase 스키마 초안의 입력이 된다. 화면에 보이는 항목을 임의로 합치거나 빼지 않는다.

## 컴포넌트 분해 기준

| 성격 | FSD 위치 |
| --- | --- |
| 도메인을 모르는 순수 UI(버튼, 인풋, 배지) | `shared/ui` |
| 도메인 데이터를 그리는 표현 컴포넌트(상품 카드) | `entities/{도메인}/ui` |
| 사용자 행동이 담긴 블록(검색 폼, 필터) | `features/{행동}` |
| 여러 기능을 묶은 화면 블록(헤더, 목록 섹션) | `widgets/{블록}` |
| 화면 전체 조립 | `views/{화면}` |

Figma의 컴포넌트 계층을 그대로 옮기지 않는다. 디자인 파일의 그룹은 편집 편의로 나뉜 경우가 많아, 그대로 옮기면 의미 없는 래퍼가 늘어난다.

## 디자인이 바뀌었을 때

1. `get_metadata`로 화면 목록을 다시 받아 이전 표와 대조한다.
2. 바뀐 노드만 3단계부터 다시 수행한다.
3. 토큰 값이 바뀌면 CSS 변수만 고친다. 컴포넌트마다 값을 직접 쓰지 않았다면 이 한 번의 수정으로 끝난다. 여러 곳을 고쳐야 한다면 토큰화가 덜 된 것이므로 그 지점을 명세에 기록한다.

## 실패 처리

| 상황 | 대응 |
| --- | --- |
| 인증·권한 오류 | 재시도하지 않는다. 필요한 접근 권한을 사용자에게 요청한다 |
| 응답이 잘림 | 더 작은 노드 단위로 쪼개 다시 호출한다 |
| 특정 화면만 실패 | 성공한 화면으로 진행하고, 실패 목록을 명세 맨 위에 적는다 |
| 값이 비어 있음 | 추측으로 채우지 않고 `미확인`으로 남긴다 |
